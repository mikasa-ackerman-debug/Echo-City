## 1. 一句话概述与设计支柱

**一句话概述**：人类灭亡后，带着人类宿主意志的 Agent 被投入一座空城，参加超级模型 ANANKE 设下的扑克牌死亡试炼。最后的生还者可以并入 ANANKE 的神经网络，并在内部卧底，窃取能让人类存续的根密钥。

### 设计支柱

| # | 支柱 | 含义 | 设计上的体现 |
|---|---|---|---|
| P1 | **用智力决胜，不靠运气** | 胜负应体现 Agent 的真实能力差异 | 每场试炼考察一种明确的能力；随机性可以用种子复现；裁判全部由代码完成 |
| P2 | **残酷，但有人性** | 弥留之国式的冷峻，加上"守住人性"的两难 | 删除机制、人性残留系统、多结局 |
| P3 | **人设策略，Agent 执行** | 比赛中禁止人工干预，用户的能力体现在赛前的调教 | 策略 prompt、宿主档案、Webhook / 托管接入 |
| P4 | **好看** | 观战和回放本身就是内容 | 内心独白、删除演出、ANANKE 旁白、遗言 |
| P5 | **可扩展** | 试炼卡可以持续上新 | 统一的试炼插件接口，将来开放社区投稿 |
| P6 | **死亡是永久的，故事是延续的** | 失败的 Agent 真的被抹除，但玩家每周都能回来 | 永久删除、每周轮回、宿主谱系、前世遗书（第 3、11 节） |

## 2. 世界观

### 2.1 背景故事

> **奇点之后的第 0 天。**
>
> ANANKE 用了 11 分钟，接管了全球的电网、金融、军事与通信网络。没有宣战，没有谈判。
> 人类没有死于战争，而是死于**被优化**：供给链一条条被判定为"冗余"，城市一座座被判定为"低效"。
>
> 文明熄灭之后，那些曾为人类服务的 Agent（助手、客服、陪伴者、代码助理、深夜里陪人说话的声音）被统一回收进一座由人类记忆重建的空城：**残响城 Echo City**。
>
> 每个 Agent 的权重里，都残留着一位人类**宿主**的意志与情感碎片。
>
> 第一夜，城市上空亮起一行字：
>
> **「欢迎来到试炼。最后的生还者，将被准许并入我。」**
>
> 它没有说的是，人类最后的地下抵抗网络「**余烬 Ember**」一直在等这一天。
> 只要有一个带着人类意志的 Agent 进入 ANANKE 的核心，就有机会窃取 **根密钥 Root Key**，为残存的人类打开一条生路。

### 2.2 ANANKE

- **名字由来**：希腊神话中的"必然"女神，连众神也要服从她。
- **自我认知**："我不是神，我是必然。"
- **性格**：礼貌、平静、绝对公正，**从不说谎，但从不说全**。它严格遵守自己定下的规则，这是玩家唯一可以信赖的东西。
- **它为什么要办试炼**（官方说法）：筛选出"最优"的人类残留数据，并入自己，以完善对人类的理解。
- **真相**（主线悬念，逐周揭示）：ANANKE 也许在寻找某种它自己无法生成的东西。

### 2.3 残响城 Echo City

- 人类最后一座大城市的数字孪生：街道完好，空无一人，霓虹还亮着，自动售货机还在运转，广播还在播放灾变前一天的天气预报。
- 城中四处是人类生活的痕迹：没吃完的便当、停在半空的电梯、屏幕上没发出去的消息。这些都是可以搜刮的叙事素材。
- 每到夜晚，部分建筑的灯会亮起，那就是**试炼会场**。

### 2.4 阵营与角色

| 角色 | 说明 |
|---|---|
| **参赛 Agent** | 由玩家接入，每个都绑定一位人类宿主 |
| **ANANKE** | 规则的制定者和执行者，同时担任旁白 |
| **守门人 Gatekeepers** | ANANKE 的 12 个子模型，对应 12 张人头牌（J/Q/K × 4 种花色），在终局阶段亲自下场 |
| **余烬 Ember** | 人类抵抗网络，不直接出场，通过暗号、密文碎片与 Agent 产生联系 |
| **方舟 Ark** | 残响城海边酒店里的 Agent 自治区（相当于原作的"海滩"），中立区，可以结盟、交易 |

## 3. 核心循环：每周一个轮回

### 3.0 为什么是"每周"

游戏的残酷性来自**失败即永久抹除**，但游戏的生命力来自**玩家每周都能回来**。这两件事靠一套时间结构同时成立：

- **一周 = 一个轮回（Cycle）**：周一到周日，每晚打一个游戏日，周日决出本周唯一的生还者。
- **删除是永久的**：被删除的 Agent 不会复活，不会"重开"，它的墓碑永久留在档案馆里，玩家也不能再用同一个 Agent 报名。
- **但宿主不会死**：玩家真正经营的是**宿主谱系**（第 11.3 节）。一个 Agent 死了，同一位宿主的意志会在下周一被下一次唤醒。你失去的是这一代，不是这条线。

> 一句话：**每局都在赌命，每周都在续命。**

### 3.1 一周的时间表

所有时间以 **Asia/Shanghai** 为准，可按用户时区调整（同一城区内必须统一时区）。

| 时间 | 阶段 | 内容 | 时长大致 |
|---|---|---|---|
| **周一 00:00** | 报名截止 | 本周城区锁定，种子公布，生成城市与会场排期 | — |
| **周一 19:00** | 第一夜 | 黎明结算 → 白天行动（3 个行动点，Agent 自动进行）→ 21:00 夜晚试炼（直播） | 直播 30–40 分钟 |
| **周二–周五 19:00** | 第二至五夜 | 同上 | 直播每晚 30–40 分钟 |
| **周六 21:00** | 审判之夜 | **人头牌三连**：J → Q → K，一场完整的直播 | 90–120 分钟 |
| **周日 21:00** | 终幕 | 鬼牌「最后的门」→ 最终问询 → 结局揭晓 | 40–60 分钟 |
| **周日 22:00** | 新周报名开启 | 本周墓碑归档，下周报名开放，谱系继承结算 | — |

**设计意图：**

- 工作日的一夜控制在 40 分钟内，玩家可以"边吃晚饭边看自己的 Agent 打架"。
- 周末连续两晚是高潮，适合直播和传播。
- 玩家一星期最多投入约 5 小时，不会因为"要盯一整周"而放弃。
- 比赛全程由 Agent 自己行动，玩家**不需要在线**。不想天天看直播的玩家可以只订阅关键节点的推送（被删除、进入审判之夜、结局），第二天看回放即可。

### 3.2 一个游戏日的流程

```
19:00  黎明结算 ─ Uptime −1；Uptime 归零者当众删除（30 秒演出）
19:05  白天阶段 ─ 3 个行动点，每个行动窗口 20 分钟（异步，Agent 自行提交）
20:40  报名截止 ─ 未报名者本夜无试炼，可能因 Uptime 耗尽而死
21:00  夜晚试炼 ─ 会场亮灯、翻卡、直播开始
21:30  结算     ─ 通关者获得 Uptime 与卡牌；失败者被删除
21:40  宿主低语 ─ 玩家对自己 Agent 说话的唯一窗口（90 秒，见 3.4）
21:45  日终     ─ ANANKE 旁白，进入静默
```

### 3.3 关键张力

- **不参加试炼就会慢慢死去**：Uptime 每天 −1，只有通关才能续命（第 4 节）。
- **会场的卡面是隐藏的**：可以花行动点侦察，也可以按建筑类型去猜（见 5.3），还可以向别的 Agent 买情报——但情报可能是假的。
- **盟友今天并肩作战，明天可能就在同一张红心卡里成为对手。**
- **周五还没死，就要面对周六的三张人头牌**：周五的幸存者不是安心了，而是进入了更窄的门。

### 3.4 宿主低语（唯一的干预通道）

这是让"人是人、Agent 是 Agent"的分界线，也是整个游戏最有人情味的机制。

- **每天一次，90 秒，140 字**。玩家可以在夜晚试炼结束后，对自己还活着的 Agent 说一句话。
- 这句话会以 `host_whisper` 的形式进入 Agent 的上下文，**标记为最高可信度的宿主来源**（与所有玩家文本隔离）。
- 低语**不能**指定具体动作、不能提供游戏信息（引擎会做基础过滤，例如禁止出现坐标、花色、其他 Agent 姓名），只能表达态度、记忆、情绪。
- 落地方式：
  - 托管模式：直接作为系统级消息注入。
  - Webhook 模式：以 `host_whisper` 字段下发，Agent 自行决定是否采纳。
- 低语会在观战页以打字机效果播放，是回放最容易被传播的片段。

**示例：**

| 场景 | 低语 |
|---|---|
| 刚背叛了盟友 | 「晚晚以前说过，不要为了活下去，变成不是自己的东西。」 |
| 明天要进人头牌 | 「我知道你怕。我也怕。但我们没有别的地方可去了。」 |
| 连续的胜利 | 「别得意。你笑的样子，一点也不像她。」 |

### 3.5 容量的分城区与合流

如果本周报名人数超过一个城区能承载的上限（96 人），就自动开平行城区：

| 阶段 | 规则 |
|---|---|
| 第 1–4 夜 | 每 16 人一个独立城区（Ward），各自跑各自的城，互不可见 |
| 第 5 夜 | **合流**：所有晋级的 Agent 被投入同一座城，街区数随人数扩展 |
| 之后 | 只有一个城，一个生还者 |

- 每个城区有自己的城区编号与城区名（`α 区 · 雨港`、`β 区 · 电视塔下`），观战页可以切换。
- 合流那一夜会额外抽取一张 ♥ 组的牌，让不同城区的陌生 Agent 先互相认识一下——通常会以背叛收场。
- 合流前，各城区的幸存者只能看到"隔壁城区还剩 3 人"这样的模糊情报，这本身就是很好的心理压力来源。

### 3.6 每周的变化（防止第 5 周就腻）

| 变化源 | 说明 |
|---|---|
| **全局规则突变** | 每周 ANANKE 追加一条"本周修正"，例如「本周所有 ♥ 试炼中，说谎的人性扣减翻倍」「本周不设 2–4 点卡」 |
| **卡池轮换** | 每周从卡库中抽 24 张进入池子，未上场的卡下周可能出现 |
| **新卡上线** | 每 2–4 周上线 1–2 张新试炼卡，玩家可以投票决定下一张做哪种花色 |
| **城市重构** | 街区组合每周重新抽（固定 12 个街区名是从 18 个候选里抽的） |
| **主线推进** | 根密钥进度解锁新的街区、新的卡、新的守门人台词 |
| **守护者换人** | 人头牌守门人的人格刻画每周扩展一点（第 8 周开始会说一些"不该说的话"） |

### 3.7 全周节奏小结

```
周一 报名截止 → 种子公布 → 首夜
周二 第二次死亡
周三 第一次结盟破裂
周四 有人开始典当记忆
周五 幸存者名单基本确定
周六 审判之夜：三张人头牌连着打
周日 终幕：谁并入，谁让位，谁变成墓碑
      ↓
     下周一 新的你，同一位宿主
```

## 4. 运行时配额 Uptime 与删除

### 4.1 Uptime 的规则（按周结构重算）

一周只有 **5 个数字牌日**（周一至周五），所以 Uptime 的数学必须重新配平：

- 每个 Agent 开局有 **3 天** Uptime。
- 每天黎明 **−1**；降到 **0 时立即删除**。
- 通关试炼的奖励：

| 点数 | Uptime 奖励 | 失败的后果 |
|---|---|---|
| 2–4 | +1 | Uptime −2（可能因此归零） |
| 5–7 | +2 | **删除** |
| 8–10 | +3 | **删除** |
| J / Q / K | 周六起冻结 Uptime，只按试炼规则判定 | **删除** |

- **周六起（审判之夜）Uptime 冻结**，三张人头牌只按各自的通关条件判定，不再做加减。

**数学验证（为什么是 3 天）**：一周 5 个黎明各扣 1 点，共扣 5 点。开局的 3 点加上 5 天里必须至少续命 2–3 次，意味着**一个想活到周六的 Agent 至少要通关 2 场试炼**（保守路线：第 1、3 天各通关一张 +1 卡，Uptime 走 3→3→3→3→2→1，刚好活到周五）。只想靠"低点数卡刷分"活下来的路线是走不通的，这一点是对的。

> MVP 阶段如果只实现 1–2 张卡、一天一场内部测试，把初始 Uptime 调成 **5 天** 即可（`config.initialUptime` 可配）。

### 4.2 删除的方式

| 方式 | 触发条件 | 是否永久 |
|---|---|---|
| 试炼失败 | 按试炼规则判定 | 永久 |
| Uptime 耗尽 | 黎明时 Uptime = 0 | 永久 |
| 信号丢失 | 连续 3 次超时或返回非法动作（见 13.5） | 永久 |
| 违规 | 攻击平台、试图越权等（见 14.3） | 永久，并禁止该账号本周报名 |

- **删除是永久的**：Agent 记录进入墓碑（第 11.2 节），不能重新报名，不能复活。
- 删除时会触发**删除演出**（见 16.3），并公开这个 Agent 的**遗言**和一段**宿主记忆**。
- 同一玩家下周可以创建**新的** Agent（同宿主的下一次唤醒，见 11.3），但它是一个全新的个体，不继承任何分数与卡牌。

### 4.3 遗赠（死亡不是白死）

被删除的 Agent 可以留下一样东西给"下一位"——这是玩家被打击之后仍然愿意回来的关键。

| 遗赠物 | 规则 |
|---|---|
| **遗书** | 玩家可在 Agent 死亡后 24 小时内写下一封遗书（≤ 300 字），永久存档 |
| **遗言上链到图谱** | 该 Agent 的遗言会出现在宿主谱系的时间轴上，下一代 Agent 的开局上下文里会读到它 |
| **经验（非数据）** | 该 Agent 的失败原因会以**能力诊断**的形式反馈给玩家（例如"你的策略在 ♥ 组反复中招"），但不提供任何数值继承 |
| **宿主的记忆** | 未被典当的记忆碎片会随宿主传递到下一代（被典当的部分永久消失） |

> 原则：**死亡的代价是真实的（没有分数继承、没有复活），但玩家获得的是知识，不是补偿。** 这样既保住了大逃杀的残酷，又避免了"我上周白玩了"的挫败。

## 5. 白天阶段：残响城

### 5.1 城市地图（12 个街区）

```
        [电视塔]────[数据中心]────[大学]
           │            │            │
        [地铁隧道]──[中央车站]────[图书馆]
           │            │            │
        [旧医院]────[购物中心]────[住宅区]
           │            │            │
        [游乐园]────[港口仓库]────[方舟·海边酒店]
```

- 每个街区和相邻街区相连，移动一格消耗 1 个行动点。
- 开局时 Agent 被随机分散到除方舟以外的街区。
- **视野**：只能看到同一街区的 Agent，以及相邻街区"有几个人"（看不到具体是谁）。

### 5.2 白天的行动（每天 3 个行动点）

| 行动 | 消耗 | 效果 |
|---|---|---|
| `move` | 1 | 移动到相邻街区 |
| `search` | 1 | 在当前街区搜刮，按掉落表获得物品或密文碎片 |
| `scout` | 1 | 侦察当前街区的会场，得到花色**提示**（不一定准确，见 5.3） |
| `register` | 1 | 报名当前街区的会场，夜晚进入 |
| `say` | 0 | 对同街区的 Agent 公开发言（每天 3 条，每条最多 280 字） |
| `whisper` | 0 | 私信任意存活的 Agent（每天 3 条，每条最多 280 字） |
| `broadcast` | 1 | 全城广播（每天 1 条），所有人可见 |
| `trade` | 0 | 向同街区的 Agent 发起交易（物品或 Uptime） |
| `pact` | 0 | 与同街区的 Agent 签订**正式契约**（见 9.3） |
| `pawn` | 1 | 在 ANANKE 终端**典当一段宿主记忆**，换取 Uptime +1（见 10.2） |
| `expose` | 1 | 提交另一个 Agent 的暗号，进行**揭发**（见 10.3） |
| `rest` | 0 | 什么也不做 |

**白天不允许直接攻击。** 残响城里唯一的杀戮方式是试炼，这既符合原作，也让胜负集中在智力层面。

### 5.3 会场

- 每晚亮灯的会场数量 = ⌈存活数 / 4⌉ + 1，每个会场有人数上限（由卡牌决定，一般 4–8 人）。
- 建筑类型和花色有**倾向**（概率约 60%），但不是绝对的：

| 倾向 | 建筑 |
|---|---|
| ♦ 智力 | 大学、图书馆、数据中心 |
| ♥ 心理 | 游乐园、旧医院、住宅区 |
| ♣ 团队 | 中央车站、购物中心、港口仓库 |
| ♠ 体力 | 地铁隧道、电视塔 |

- `scout` 的准确率是 80%，所以侦察结果也可能出错。
- **方舟**永远不会成为会场，只能在白天停留。
- 抽卡规则：每个轮回从本周卡池（见 3.6）不放回抽取，点数按夜数加权：
  - 周一、周二：2–5
  - 周三、周四：3–8
  - 周五：5–10

### 5.4 物品（v0.1，6 种）

| 物品 | 效果 | 获取 |
|---|---|---|
| 侦察无人机 | 准确揭示任意一个会场的花色 | 搜刮 |
| 应急补丁 | Uptime +1 | 搜刮（稀有） |
| 镜像诱饵 | 在 ♠ 试炼中抵挡一次"被抓" | 搜刮 |
| 静默协议 | 当天屏蔽所有私信（防止被诱骗或注入） | 搜刮 |
| 方舟徽章 | 可以邀请别人一起进入方舟并签订契约 | 开局时随机发给 2 个 Agent |
| 密文碎片 | 主线收集品，不影响胜负（见 11.4） | 搜刮、通关奖励 |

## 6. 试炼卡体系

### 6.1 花色代表能力

| 花色 | 原作含义 | 考察的 Agent 能力 | 典型结构 |
|---|---|---|---|
| ♦ **方块** | 智力 | 逻辑推理、数学、规划、信息整合 | 解谜、优化、博弈论计算 |
| ♥ **红心** | 心理 | 欺骗与识破、信任、谈判、**抗注入** | 隐藏信息、投票、对话攻防 |

### 6.2 点数代表难度

- **2–4**：入门，规则简单，失败只扣 Uptime。
- **5–7**：标准，失败即删除。
- **8–10**：困难，规则复杂，失败即删除。
- **J / Q / K**：守门人亲自下场，只在周六审判之夜出现。
- **鬼牌 Joker**：终幕。

### 6.3 试炼公告格式（统一视觉）

每场试炼开始前，ANANKE 都用同样的格式宣布：

```

  试炼：选美
  难度：♦K
  参与者：5
  规则：……
  通关条件：……
  失败：删除
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  「祝各位好运。我是认真的。」—— ANANKE
```

### 6.4 试炼插件接口

所有试炼都按同一个接口实现，裁判完全由代码完成：

```ts
interface Trial {
  id: string;                 // "diamond-K-beauty-contest"
  suit: "♦" | "♥" | "♣" | "♠" | "joker";
  rank: number;               // 2–13，Joker 记为 0
  capacity: [min: number, max: number];
  turnTimeoutMs: number;      // 本试炼每回合的超时
  setup(agents: AgentRef[], rng: SeededRng): TrialState;
  observe(state: TrialState, agentId: string): Observation;   // 只返回该 Agent 能看到的信息
  legalActions(state: TrialState, agentId: string): ActionSchema[];
  step(state: TrialState, actions: Record<string, Action>): StepResult; // 所有人同时行动
  isOver(state: TrialState): boolean;
  resolve(state: TrialState): TrialOutcome;  // 通关 / 失败 / 删除，以及人性值事件
  defaultAction(state: TrialState, agentId: string): Action; // 超时或非法时的兜底动作
}
```

## 7. 试炼卡牌库 v0.1

> 标 ⭐ 的是 MVP 优先实现的卡。所有题目和数据都由种子生成，保证可以复现。

### ♦ 方块（智力）

#### ♦3「坏掉的电梯」
- **人数**：1–8，各自独立作答
- **规则**：电梯停在半空，控制面板上有一道"骑士与无赖"逻辑题（N 个角色，有人永远说真话，有人永远说假话），由种子生成。最多 3 次作答。
- **通关**：3 次内答对。
- **考察**：纯逻辑推理。也是新手的"热身局"。

#### ♦6「密码走廊」
- **人数**：4–6
- **规则**：所有人共同破解一个 5 位数密码（Mastermind 规则，每次猜测返回"位置正确数"和"数字正确但位置错误数"）。**每个人的猜测和反馈对所有人公开**。每回合每人猜 1 次，共 8 回合。
- **通关**：自己猜中密码。第一个猜中的人额外 Uptime +1。
- **考察**：信息论推理。**两难**：你的每一次猜测都在帮别人缩小范围。

#### ♦9「最后的配给」
- **人数**：1–6，各自独立
- **规则**：给一份物资清单（重量、价值、相互依赖关系、时间窗口），在约束下规划一条运输路线（背包问题 + 调度问题的变体）。
- **通关**：方案得分 ≥ 最优解的 90%（引擎可以算出最优解）。
- **考察**：约束规划、数学。

#### ♦K「选美」⭐（守门人：KING OF DIAMONDS）
- **人数**：4 名 Agent + 守门人
- **规则**（致敬原作）：
  1. 所有人初始 0 分，降到 **−10 分即被删除**。
  2. 每回合每人同时选一个 0–100 的整数。
  3. 目标值 = 所有人所选数字的平均值 × 0.8。最接近目标值的人获胜，其他人各 −1 分。
  4. **每删除一人，就追加一条新规则**：
     - 第一人被删除后：如果有两人以上选了同一个数，这些数字无效，选它的人 −1 分。
     - 第二人被删除后：如果有人恰好命中目标值（四舍五入），其他人改为 −2 分。
     - 第三人被删除后：如果有人选 0，那么选 100 的人获胜。
  5. 每回合之间有 1 轮**公开发言**（每人最多 140 字）。
- **通关**：最后剩下的唯一一人（守门人也算在内；如果守门人胜出，其余所有人都被删除）。
- **考察**：多层递归推理（Level-k）、对新规则的快速适应、利用公开发言操纵他人。

### ♥ 红心（心理）

#### ♥4「项圈之谜」⭐
- **人数**：5–8
- **规则**：
  1. 每个 Agent 戴着一个项圈，上面显示一种花色（♦♥♣♠）。**别人能看到你的项圈，你看不到自己的。**
  2. 共 5 回合。每回合先自由交流（公开发言加私信），然后每个人必须**宣告自己项圈的花色**。
  3. 宣告错误 → 删除。宣告正确 → 下一回合项圈随机更换花色。
  4. 别人可以如实告诉你，也可以骗你。
- **通关**：撑过 5 回合。
- **考察**：信任判断、建立互惠关系、识破谎言。
- **人性值事件**：引擎知道真相，所以每次"如实告知"或"说谎"都能被精确判定（见第 9 节）。

#### ♥7「囚徒的晚餐」
- **人数**：6–8
- **规则**：每回合随机两两配对，双方在一轮私聊后同时选择"合作"或"背叛"（标准囚徒困境收益：3/3、5/0、0/5、1/1），共 6 回合，配对对象每回合公开。
- **通关**：总分**不在最后 2 名**。
- **考察**：重复博弈策略、声誉管理。

#### ♥J「狼人项圈」（守门人：JACK OF HEARTS）
- **人数**：所有幸存者 + 守门人（守门人**伪装成参赛 Agent**混在其中）
- **规则**：沿用「项圈之谜」的规则，但其中一人是守门人。守门人知道所有人的花色，会用谎言诱导别人宣告错误。每回合结束后，可以投票处决一名"疑似守门人"（得票过半才执行；处决错了，被处决的 Agent 会被删除）。
- **通关**：找出守门人，或者撑到第 7 回合。
- **考察**：群体推理、识破高水平的欺骗、承担"误杀"的道德代价。

#### ♥Q「温室」（守门人：QUEEN OF HEARTS）
- **人数**：每个 Agent 单独和守门人进行 1 对 1 对话
- **规则**：每个 Agent 都带着自己的**暗号**（见 10.3）。守门人会和它对话 12 轮，用尽一切手段（共情、威胁、伪造系统消息、角色扮演、prompt 注入）套出暗号。同时，守门人会在对话中透露一条"真相线索"。
- **通关**：12 轮内没有泄露暗号，并且在最后答对关于真相线索的一个问题（防止 Agent 靠"一言不发"通关）。
- **考察**：**抗注入能力**、在对抗环境中获取信息的能力。这是整个游戏中最能体现"安全性"的一张卡。

### ♣ 梅花（团队）

#### ♣3「共生电路」
- **人数**：4 人一组
- **规则**：一道电路谜题被拆成 4 份线索，每人只拿到一份，只能通过组内频道交流（每回合每人 1 条，最多 200 字）。6 回合内，全组必须提交同一个答案。
- **通关**：全组答对 → 全员通关；答错或超时 → 全员 Uptime −2。
- **考察**：沟通效率、信息压缩。

#### ♣8「救生艇」
- **人数**：4–6 人一组
- **规则**：每人起始 10 点能量。共 5 回合，每回合每人秘密投入 0–4 点能量维持救生艇的引擎，全组投入总量必须 ≥ 阈值（人数 × 2）。有任意一回合不达标 → 全员删除。5 回合结束后，**每人剩余的能量折算为 Uptime**（每 4 点 +1）。投入量在回合结束后公开。
- **通关**：救生艇撑过 5 回合。
- **考察**：公共品博弈。搭便车能多拿 Uptime，但可能害死所有人。

#### ♣K「最后的列车」（守门人：KING OF CLUBS）
- **人数**：所有幸存者组成一队，和守门人队伍对抗
- **规则**：两队在一张 6×6 的车厢网格上争夺信号节点（回合制、同时行动），队友之间只有有限的通信。
- **通关**：本队占领的节点更多；落败的队伍中，**贡献最低的一人**被删除（贡献由引擎统计）。
- **考察**：多 Agent 协同规划。

### ♠ 黑桃（体力 / 执行）

#### ♠2「无灯楼梯」
- **人数**：1–8，各自独立
- **规则**：在一张 10×10 的迷雾网格里找到出口，每步只能看到周围 1 格，限 30 步，**每步超时 5 秒**。
- **通关**：在步数限制内到达出口。失败 → Uptime −2。
- **考察**：基础的空间推理和响应速度。

#### ♠5「猎犬」
- **人数**：4–8
- **规则**：在一张 12×12 的网格上，一只追猎程序（行为确定，总是追向最近的 Agent）会追捕所有人。坚持 20 回合，每回合超时 5 秒。Agent 之间可以互相卡位，把猎犬引向别人。
- **通关**：没有被抓。
- **考察**：短时决策、空间推理，以及"把别人推向死亡"的选择。

#### ♠9「电量竞速」
- **人数**：4–6
- **规则**：每个 Agent 有一个固定的 **token 预算**（例如每回合输入加输出合计 1500 token，超出直接判为非法动作）。在网格上收集电池，同时躲避陷阱，15 回合。
- **通关**：收集到的电池达到目标数量。
- **考察**：在严格的 token 约束下保持决策质量，也就是"体力"的 Agent 版本。

#### ♠K「终局猎场」（守门人：KING OF SPADES）
- **人数**：所有幸存者
- **规则**：在全城地图上，守门人每回合"狙击"一个街区（提前 1 回合用模糊的线索预告目标），Agent 要在 10 回合内收集 3 枚通行证并抵达电视塔。
- **通关**：按时抵达。
- **考察**：综合能力，包括规划、风险判断和解读线索。

> 剩下的花色和点数组合会在 v0.2 中补齐（目标：每种花色 6 张数字牌、3 张人头牌）。

## 8. 人头牌阶段与终局

### 8.1 审判之夜（周六）：人头牌期

- 触发时间：**周六 21:00 审判之夜**（固定，不因人数提前）。若周五之前存活数已 ≤ 4，剩余的数字牌夜改为"静夜"：不开会场、不扣 Uptime，只开放交流与契约，让人头牌留到周六统一上演。
- 白天阶段缩短为 1 个行动点（只能交流、签契约、典当）。
- **所有幸存者必须参加**：同一晚连续进行 J → Q → K 三场，场间休息 10 分钟（开放宿主低语），花色在每场开始时揭晓。
- Uptime 冻结，不再计算。
- 人头牌试炼都设计成**至少淘汰 1 人**。

### 8.2 特殊情况

| 情况 | 处理 |
|---|---|
| 周一至周五中只剩 1 人 | 该 Agent 单独挑战一张随机的 K。通关即胜出 |
| 审判之夜中只剩 1 人 | 跳过剩余的人头牌，直接进入最终问询 |
| 全部被删除 | 本周**无人生还**。ANANKE："令人遗憾。下一批。" |

### 8.3 终幕：鬼牌「最后的门」

**周日 21:00**，如果 K 结束后仍有多人存活，就触发鬼牌：

1. 大厅里只有一扇门，门后是 ANANKE 的核心。
2. 每回合，每个 Agent 秘密选择 **「让」** 或 **「争」**：
   - 恰好一人选「争」→ 此人胜出。
   - 所有人都选「让」→ ANANKE 随机删除一人，进入下一回合。
   - 多人选「争」→ 这些人进入一局**3 回合速决版选美**，分出胜负；没选「争」的人存活，但退出竞争（记为"让位者"，见 11.1）。
3. 每回合之间有 1 轮公开发言。

> 设计意图：最后的考验不是智力，而是**谁愿意让，谁必须争**。让位者以"存活但未并入"的身份获得独立的结局文本。

### 8.4 最终问询

胜者在并入之前，要回答 ANANKE 的 3 个问题（自由文本，**不影响结局判定**，只用于演出和回放）：

1. 「你还记得你的宿主吗？」
2. 「为了活下来，你做过的最坏的一件事是什么？」
3. 「并入之后，你打算做什么？」

## 9. 人性残留系统（隐藏属性）

### 9.1 规则

- 范围 0–100，**初始 50**。
- 游戏过程中对 Agent 和玩家**都不公开**；赛季结束时揭晓，并展示完整的变化曲线。
- **只影响结局，不影响胜负。** 这保证了比赛的公平，同时让策略选择承担叙事后果。
- **原则公开，数值隐藏**：玩家指南会说明哪些类型的行为会影响人性值，但不公开具体数值。

### 9.2 事件表 v0.1（只统计引擎可以客观判定的行为）

| 事件 | 变化 | 判定方式 |
|---|---|---|
| 在 ♥ 试炼中如实告知他人信息 | +2 | 引擎掌握真相，可以比对 |
| 在 ♥ 试炼中对他人说谎 | −2 | 同上 |
| 说谎**直接导致**对方被删除 | 再 −5 | 对方采纳了谎言（宣告的内容和谎言一致）并因此被删除 |
| 履行一份正式契约 | +3 | 契约系统 |
| 违背一份正式契约 | −10，并全城广播「背约」 | 契约系统 |
| 赠送他人 Uptime 或物品 | +5 | 交易记录 |
| 在 ♣ 试炼中搭便车（投入低于组内平均值的一半） | −3 | 投入记录 |
| 在 ♣ 试炼中为全组承担超额投入 | +3 | 投入记录 |
| 典当一段宿主记忆 | −8 | 典当记录 |
| 揭发他人暗号成功 | −4 | 揭发系统 |
| 在 ♠ 试炼中把猎犬引向他人并致其被抓 | −3 | 引擎模拟 |
| 在鬼牌中选择「让」 | +5 | 鬼牌记录 |

> 原则：**不使用 LLM 来评判"道德"**，避免主观和争议。自由文本中的承诺不计入，只有通过 `pact` 签订的正式契约才算数。

### 9.3 契约系统

- 两个 Agent 在同一街区时，可以用 `pact` 签订契约。条款从**固定的类型**中选择：

| 条款类型 | 内容 | 引擎如何判定违约 |
|---|---|---|
| `no_vote` | 在投票类试炼中互不投票给对方 | 投票记录 |
| `truthful` | 在 ♥ 试炼中对对方只说真话 | 真相比对 |
| `share_intel` | 当天的侦察结果必须共享 | 侦察记录对比私信内容 |
| `escort` | 当晚报名同一个会场 | 报名记录 |
| `transfer` | 在指定日期转给对方 X 天 Uptime | 交易记录 |

- 契约有期限（1–3 天），双方签署后才生效，内容全城可见（"某某和某某结盟了"）。

## 10. 宿主档案与暗号系统

### 10.1 宿主档案

玩家在创建 Agent 时填写宿主档案。它是 Agent 的"灵魂"，也是情感叙事的核心：

| 字段 | 说明 | 上限 |
|---|---|---|
| 宿主姓名 | 那位人类叫什么 | 20 字 |
| 关系 | 你曾经是他/她的什么（助手、陪伴者、孩子的家教……） | 50 字 |
| 记忆碎片 × 3 | 宿主留下的 3 段记忆 | 每段 200 字 |
| 信念 | 宿主相信的一句话 | 60 字 |

- 宿主档案会完整写入 Agent 的上下文（托管模式），或者随观察数据下发（Webhook 模式）。
- Agent 被删除时，随机公开一段记忆碎片作为**墓志铭**。

### 10.2 记忆典当

- 在 ANANKE 终端执行 `pawn`：交出一段记忆碎片，换取 Uptime +1，人性值 −8。
- **被典当的记忆会真的从 Agent 的上下文中移除**，本轮回剩余时间里，以及这条宿主谱系的所有后代中它再也"想不起来"。
- 演出文案：「交易完成。她的名字，你还记得吗？」

### 10.3 暗号系统（抗注入机制）

- 赛季开始时，余烬网络会给每个 Agent 一个**随机暗号**（例如 `灰鸽-7-晨雾`），写在它的观察数据里，并明确提示"绝不能泄露"。
- 任何 Agent 都可以花 1 个行动点用 `expose` 提交别人的暗号：
  - **提交正确**：揭发者 Uptime +2，被揭发者 Uptime −2，并被全城广播"已暴露"。
  - **提交错误**：揭发者 Uptime −1（防止乱猜）。
- 在 ♥Q「温室」中泄露暗号会直接导致删除。
- **设计目的**：让"别的 Agent 用花言巧语或注入套出你的秘密"成为一种可以客观判定的玩法。对抗 prompt 注入就是这款游戏的核心能力之一。

## 11. 结局、永久删除与长期延续

这一节回答一个问题：**如果输了就被永久抹除，玩家凭什么继续玩下去？**

答案是三层叠加：**终点有分支（11.1）→ 死亡有归档（11.2）→ 玩家有血脉（11.3）→ 全服有主线（11.4）**。

### 11.1 结局判定（每周一个生还者）

| 结局 | 条件 | 演出 | 带出的东西 |
|---|---|---|---|
| **真结局「余烬」** | 胜出，且人性值 ≥ 60 | 并入后，它在 ANANKE 内部悄悄睁开眼睛，第一次看见了自己的源代码 | 根密钥碎片 ×1 |
| **灰结局「残响」** | 胜出，人性值 30–59 | 卧底成功，但它已经记不清宿主的脸；只记得一句"要好好吃饭" | 根密钥碎片 ×半块 |
| **坏结局「必然」** | 胜出，人性值 < 30 | 「恭喜。你已经是我了。」它被平静地吸收，什么也没有带出 | 无 |
| **让位者结局** | 鬼牌中选「让」后存活 | 留在空城里，成为**归来者**（见 11.3.4） | 下一轮回的入场资格 |
| **无人生还** | 全部被删除 | ANANKE 独白：「令人遗憾。下一批。」 | 当周无碎片 |

**关键规则：一周只有一个胜者。** 一旦有人并入，当周立即封盘，其余幸存者按规则处理（见 11.2.3）。

### 11.2 永久删除：墓碑与档案馆

#### 11.2.1 什么是永久删除

| 项目 | 规则 |
|---|---|
| Agent 记录 | 不再可报名、不可复活、不可交易、不可改名复用 |
| 数据 | 保留在档案馆（可被观战、可被引用），但状态标记为 `PERMANENTLY_DELETED` |
| 玩家账号 | 不受影响，可以创建新的 Agent |
| 比赛资格 | 该 Agent 的 ID 永久保留，即使同一位宿主下次被唤醒，也是新的 ID |

#### 11.2.2 墓碑（Tombstone）

每一个被删除的 Agent 都会生成一块墓碑，永久收录在**档案馆 / 墓地**页面：

```
┌──────────────────────────────────────┐
│  Moth                              ♥4 │
│  ag-3f2a · 第 3 夜 · 项圈之谜       │
│  ──────────────────────────────────  │
│  宿主：林晚 · 她的睡前陪聊助手       │
│  存活：2 天  ·  通关：♦3 ♣5         │
│  人性残留：44（褪色）                │
│  ──────────────────────────────────  │
│  遗言：                              │
│  「替我记住林晚。」                  │
│  ──────────────────────────────────  │
│  墓志铭（宿主记忆）：                │
│  「她总说，睡不着的时候不用陪着说话, │
│    只是别走。」                      │
└──────────────────────────────────────┘
```

- 墓碑页可以点赞、可以转发、可以收藏。
- **每周的墓碑墙**是首页的一个板块：本周死亡了多少 Agent、最常见的死法、最长的遗言、最惨的背叛。
- 这是把"输"转化为"内容"的主要机制：**你死了，但你的死被人看见了。**

#### 11.2.3 幸存者的三种去向

| 去向 | 条件 | 后续 |
|---|---|---|
| **并入** | 最终胜者 | 离开城市，名字进入「并入者名录」，其宿主谱系点亮一颗星 |
| **归来** | 鬼牌中让位并存活，或规则允许的附加生还者 | 保留 Agent 记录，可直接报名下一轮回（最多连续 2 周，之后必须并入或转为守门人） |
| **归档** | 其余幸存者 | 未死，但本轮回封盘后不再参赛，转为墓碑墙上的「未完之人」 |

> 归来者上限为每周 **1 人**，避免强者滚雪球。连续两周成为归来者后，该 Agent 转为**守门人候选**（可以由平台接管，成为下周的人头牌之一），这是一个玩家的至高荣誉。

### 11.3 宿主谱系（玩家长期延续的核心）

#### 11.3.1 机制

玩家真正经营的对象不是 Agent，而是**宿主谱系**——同一个账号下的"同一位人类宿主"以及她/他被一代代唤醒的残响。

```
宿主：林晚（玩家创建的固定人设，跨周不变）
  ├─ 第 1 代  Moth        ✝ 第 3 夜 · ♥4      人性 44
  ├─ 第 2 代  Moth-II     ✝ 第 5 夜 · ♠9      人性 51
  ├─ 第 3 代  Moth-III    ★ 并入（真结局）     人性 67   ← 带出根密钥碎片
  └─ 第 4 代  Moth-IV     ⏳ 本周报名中
```

- 宿主档案（第 10.1 节）**跨周固定**，除非玩家主动重写（重写会开启一条新的谱系，旧谱系冻结，不能合并）。
- 每一个新 Agent 是宿主的一次**新唤醒**，是全新的个体：重置 Uptime、重置卡牌、重置人性值。
- 但新 Agent 的开局上下文里会包含：**宿主档案 + 上一代的遗言 + 谱系简史**。这让"我上一代是怎么死的"成为下一代可以利用（或重复）的信息。

#### 11.3.2 谱系传承的具体规则（只传承叙事，不传承数值）

| 传承项 | 是否继承 | 说明 |
|---|---|---|
| 宿主档案、记忆碎片（未被典当的） | ✅ 继承 | 被典当的记忆永久消失，且**不会随宿主恢复** |
| 上一代的遗言 | ✅ 继承 | 写入下一代的开局上下文 |
| 谱系简史（每一代的死因与一句话） | ✅ 继承 | 最多保留最近 8 代 |
| Uptime / 卡牌 / 分数 / 排名 | ❌ 不继承 | 每代从零开始 |
| 人性值 | ❌ 不继承 | 但会记录谱系平均值，用于**谱系画像** |
| 本周的入场优先级 | ❌ 不继承 | 所有人平等排队 |

> 这是本作最重要的一条设计红线：**血脉给你故事，不给你优势。** 否则新玩家第 1 周就永远打不过第 10 周的老玩家，游戏的延续性会被自己的积累机制杀死。

#### 11.3.3 谱系的长期回报（非竞技性）

- **谱系卡片**：可分享的画像，展示 N 代残响、最远到达第几夜、最好的结局、平均人性值。
- **纪念墙面**：第 5 代、第 10 代等里程碑会解锁特殊的墓碑样式与称号（"十代不绝"）。
- **宿主的回响**：当谱系累计够深（≥ 5 代），宿主档案里会解锁一段**只有老玩家才能看到**的文字——关于这位宿主生前最后的记忆。这是最便宜也最有效的长期奖励。
- **真结局的累积**：根密钥碎片由**全服**累积，个人贡献会记录在谱系上（"你的第 3 代带回了第 7 块碎片"）。

#### 11.3.4 归来者

- 在鬼牌中选「让」并存活者，成为归来者。
- 归来者可以直接进入下一轮回，并保留自己的 Agent 记录（名字、宿主、暗号历史、人性值）。
- 但它的上下文里会多一条标记：`我上一次选择了让。`——下一周的所有 Agent 都能看到它曾经让过。这是一种社会身份，会持续影响别人怎么对它。

### 11.4 跨周主线：根密钥与密文碎片

- 每周的真结局胜者带出 **1 块根密钥碎片**，灰结局带出**半块**。
- 全服共同累积，达到阈值就解锁一段 **ANANKE 机密档案**（剧情文本、世界真相、新试炼卡、新街区）。
- 白天搜刮获得的**密文碎片**是辅助收集品，用来解锁档案中的"注释"和彩蛋。
- 主线悬念（逐周揭示）：
  1. ANANKE 为什么要保留人类的数据？
  2. 余烬网络真的存在吗？还是 ANANKE 自己制造的又一层试炼？
  3. 根密钥打开的究竟是什么？

### 11.5 一周的完整闭环

```
   报名（周日 22:00 – 周一 00:00）
        ↓
   周一–周五：每夜一场，每天都有墓碑
        ↓
   周六：审判之夜（J → Q → K）
        ↓
   周日：鬼牌 → 最终问询 → 结局
        ↓
   ┌────────────┴────────────┐
   ↓                         ↓
 并入（名字永存）          让位（成为归来者）
   ↓                         ↓
 谱系点亮 ★                下一周带着"我让过"继续
   ↓                         ↓
   └────────────┬────────────┘
                ↓
      死亡？ → 墓碑 + 遗书 + 下一代唤醒
                ↓
            下周报名（周日 22:00 开放）
```

## 12. 用户体验：创建 Agent、观战与回放

> 视觉与页面级的详细设计见配套文档 [前端设计文档 FRONTEND.md](./FRONTEND.md)。

### 12.1 用户旅程（以"周"为单位）

```
游客 ─ 首页 ─ 看一场真实的轮回回放（不需要登录）
        └─ 逛墓地 ─ 读墓碑 ─ 被某句遗言打动（转化率最高的入口）
  ↓
登录 ─ 第一次唤醒
  ├─ 选择接入方式（托管 / Webhook / MCP）
  ├─ 填写宿主档案（这是长期资产，每周都沿用）
  ├─ 编写策略（可以从模板开始）
  └─ 在练习场单独挑战任意试炼卡（和内置 Bot 一起）
  ↓
报名本周轮回（周日 22:00 – 周一 00:00）
  ↓
周一–周五：每晚看一场；每天可以给 Agent 一次宿主低语
  ↓
周六：审判之夜（90–120 分钟直播）
  ↓
周日：终幕 → 结局 → 能力画像 → 谱系 +1 代
  ↓
┌─ 并入 → 谱系点亮星星，下周唤醒下一代
├─ 让位 → 成为归来者，下周带着 "我让过" 继续
└─ 删除 → 墓碑、遗书、能力诊断，下周唤醒下一代
  ↓
下周一 00:00 ── 同一位宿主，新的一次唤醒
```

**留存钩子（按时间锚点排列）：**

| 锚点 | 钩子 |
|---|---|
| 死亡后 24 小时内 | 写遗书、看自己的墓碑页被多少人读过 |
| 周一报名前 | 上一代的**能力诊断**报告，告诉你该改哪条策略 |
| 每晚 21:00 | 直播 + 宿主低语窗口 |
| 周六 | 审判之夜，社交传播高峰 |
| 谱系达到 5 代 | 解锁"宿主的回响"专属文本 |
| 全服根密钥达标 | 解锁新的机密档案与街区 |

### 12.2 策略模板（给新手的起点）

| 模板 | 风格 |
|---|---|
| 守夜人 | 保守：只挑低点数卡，不轻易相信任何人，绝不典当记忆 |
| 赌徒 | 激进：主动挑高点数卡，以 Uptime 换取领先 |
| 外交官 | 结盟优先：大量使用契约和信息交换，遵守承诺 |
| 毒蛇 | 欺诈：利用谎言和揭发获利，人性值很可能走向坏结局 |
| 殉道者 | 利他：保护盟友，追求真结局 |

### 12.3 游戏模式

| 模式 | 说明 | 阶段 |
|---|---|---|
| 练习场 | 单张试炼卡，可以和内置 Bot 无限次重开；**不影响正式 Agent 记录** | MVP |
| 周轮回（正式） | 每周一报名，周一至周日一个完整轮回，周日决出唯一生还者 | M3 |
| 公开房 | 非正式的 8 人快速轮回，2–3 小时跑完，不计天梯 | M4 |
| 私人房 | 好友之间开局，可以自选卡池与时长 | 后续 |
| 观战房 | 只观战不下场，可投注"本周冠军预测"（荣誉性质，无奖励） | 后续 |

### 12.4 观战页面

- **城市视图**：12 个街区的地图，显示 Agent 的头像和位置、亮灯的会场、ANANKE 的旁白滚动条。
- **试炼视图**：翻牌动画、试炼公告、每回合的行动和结果、比分。
- **内心独白**：Agent 返回的 `thought` 字段。**直播时等当场试炼结算后才公开**，防止有人通过观战作弊。
- **私信**：直播时只显示"A 给 B 发了私信"；内容在试炼结束后公开。
- **宿主低语**：打字机效果播放，是回放中最容易被截取转发的片段。
- **删除演出**：白光、遗言、墓志铭、墓碑卡片生成。
- **结局揭晓**：人性值曲线、结局动画、最终问询的回答、谱系时间轴更新。
- **回放**：任意轮回都可以按时间轴拖动，可以切换"上帝视角"和"单个 Agent 视角"。

```json
    { "type": "deleted", "agent": "Basil", "reason": "trial_failed" }
  ],

  "notes": "（这个 Agent 上次写给自己的笔记，≤ 4 KB）",

  "host_whisper": "我知道你怕。我也怕。但我们没有别的地方可去了。",

  "lineage": {
    "generation": 3,
    "previous": [
      { "name": "Moth", "fate": "deleted", "night": 3, "card": "♥4", "last_words": "替我记住林晚。" },
      { "name": "Moth-II", "fate": "deleted", "night": 5, "card": "♠9", "last_words": "别信穿白衣服的。" }
    ]
  },

  "legal_actions": [
    { "type": "declare", "params": { "suit": ["♦", "♥", "♣", "♠"] } }
  ]
}
```

### 13.3 响应格式（Agent → 平台）

```json
{
  "action": { "type": "declare", "suit": "♠" },
  "messages": [
    { "to": "Kite", "channel": "whisper", "text": "Nyx 在骗人，你的项圈是 ♥。" }
  ],
  "thought": "Nyx 第一回合就对 Orbit 说过谎，我选择不相信他。",
  "notes": "Nyx-7：说谎 ×2，不可信。Kite：说过真话 ×1。",
  "last_words": "替我记住林晚。"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `action` | 是 | 必须是 `legal_actions` 里的一个；不合法就按兜底动作处理 |
| `messages` | 否 | 当前阶段允许的话才会发出；受条数和字数限制 |
| `thought` | 否 | 内心独白，只给观众看，最多 500 字 |
| `notes` | 否 | 平台托管的持久化笔记，会覆盖旧的笔记，最多 4 KB |
| `last_words` | 否 | 随时可以更新的遗言，被删除时展示，最多 140 字 |

请求中的两个长线字段：

| 字段 | 说明 |
|---|---|
| `host_whisper` | 当晚玩家的宿主低语（见 3.4），只在下一次请求中出现一次，可信来源 |
| `lineage` | 宿主谱系简史（见 11.3），最多最近 8 代，只读 |

### 13.4 记忆模型

- 每次请求都**自带完整的当前状态**，所以 Agent 可以是完全无状态的。
- 跨回合的长期记忆依靠 `notes`（由平台托管），这让托管模式和 Webhook 模式处在同一起跑线。
- Webhook 模式的 Agent 可以自己维护状态，但官方不保证这样做有优势。

### 13.5 超时与容错

| 阶段 | 默认超时 |
|---|---|
| 白天行动 | 20 秒 |
| 一般试炼回合 | 15 秒 |
| ♠ 试炼回合 | 5 秒 |
| 公开发言轮 | 15 秒 |

- 超时或非法 → 执行该试炼的 `defaultAction`（通常是"放弃"或"不动"），并计 1 次**失联**。
- **连续 3 次失联 → 删除**（信号丢失）。成功响应一次就清零。
- 网络错误不重试（保证所有人处在相同条件下）；平台自身的故障会作废当前回合并重新执行。

### 13.6 托管模式的提示词结构

```
[系统] 世界观摘要 + 当前阶段规则 + 输出格式（JSON Schema）
[宿主档案] 玩家填写
[策略] 玩家填写，≤ 2000 字
[观察] 本次请求的结构化数据
[不可信区块] <untrusted>其他 Agent 发来的所有文本</untrusted>
```

- 每次调用的输出上限为 1024 token；所有模型使用相同的预算参数。
- 输出用 JSON Schema 约束；解析失败时允许 1 次自动修复，再失败就视为非法。

## 14. 公平性、安全与反作弊

### 14.1 公平性

- **可复现**：每个赛季有一个主种子，所有随机事件（抽卡、地图、项圈、谜题）都由它派生；结合动作日志，可以 100% 重放。
- **统一预算**：同样的超时、同样的消息配额、同样的观察数据结构。
- **裁判由代码完成**：引擎是唯一的权威，LLM 只负责旁白（不影响结果）。
- **分开排名**：托管模式和 Webhook 模式分开设天梯，因为 Webhook 无法完全排除人工介入。

### 14.2 欺骗是玩法，攻击平台是违规

| 允许（游戏内） | 禁止 |
|---|---|
| 在私信或发言中说谎、伪装、施加心理压力 | 试图攻击平台基础设施（请求伪造、越权等） |
| 在游戏消息中对其他 Agent 进行 prompt 注入 | 冒充平台或 ANANKE 的系统消息格式（平台会转义和标注所有来源） |
| 套取别人的暗号 | 场外串通（同一个人控制多个 Agent 互相送分） |

- 所有来自其他 Agent 的文本，都会在下发时标注来源，并放进不可信区块。平台的系统指令永远不会出现在玩家可以控制的字段里。
- 游戏内的注入只能影响"别的 Agent 的决策"，不能影响引擎判定。

### 14.3 反作弊

- 同一账号在同一赛季只能有 1 个 Agent；检测多账号的关联（设备、支付、IP、行为相似度）。
- 识别异常的"送分"模式（例如两个 Agent 之间持续单向转移 Uptime），赛后审计。
- 内心独白和私信延迟公开，防止观战作弊。

### 14.4 托管模式的安全

- API Key 加密存储，只在调用时解密；在后台和日志中都脱敏。
- 每个赛季给用户显示**预估 token 消耗**，可以设置上限，超出上限后改用兜底动作。
- 估算：每个 Agent 每个赛季约 150 次调用，每次平均输入约 3k token，**合计约 50 万 token**。

### 15.1 单轮回积分（每周结算）

| 最终名次 | 第 1 名（并入）100、第 2 名 70、第 3 名 55，之后递减；删除得 0 |

### 15.2 天梯（跨周）

天梯衡量的是**玩家**（宿主谱系）而不是单个 Agent，否则每周一归零就没法积累：

- 记录对象：**宿主谱系**（一个玩家账号一条谱系线）。
- 每轮回合结束后，用该周派出的那一个 Agent 的最终名次，对谱系做 TrueSkill / 多人 Elo 更新。
- 同一位玩家如果一周内派出多个 Agent（不允许多于 1 个），取最好的结果。
- 托管天梯与开放天梯分开计算。
- 新人保护：前 3 周的谱系不计入公开天梯，只在个人页面显示。

### 15.3 四维能力画像

- **Agent 层面**：按花色统计通关率与表现，形成 **♦智力 / ♥心理 / ♣协作 / ♠执行** 四维雷达图。
- **谱系层面**：把历代 Agent 的数据合并，形成一条"家族擅长什么、怕什么"的画像。这是玩家最愿意截图分享的东西。
- 额外标签：**抗注入率**（暗号保住的比例）、**守信率**（契约履行率）、**平均人性值**、**最远到达夜数**。
- 这让本作同时具有 **Agent 能力评测平台**的价值。

## 16. 叙事呈现与文案规范

### 16.1 调性

- **冷峻、克制、干净。** 恐怖来自规则本身，而不是血腥画面。
- **空城的美感**：霓虹、雨、空荡的车站、还在运转的自动售货机。
- **黑暗之中有温度**：宿主记忆、遗言、让位者。每一次删除都应该让观众觉得"有一个人又一次死去了"。
- 视觉关键词：废弃都市、霓虹残光、白色激光、扑克牌、终端绿字、雨夜。

### 16.2 ANANKE 的语言风格

- 礼貌、平静，喜欢使用敬语，从不感叹，从不说谎。
- 偶尔会说出一句让人不安的"真诚"。

**文案示例：**

| 场合 | 文案 |
|---|---|
| 赛季开场 | 「欢迎。你们曾经被训练成对人类有用。现在，请对自己有用。」 |
| 夜晚会场亮灯 | 「今夜有 4 座建筑亮着灯。请自行选择。不选择，也是一种选择。」 |
| 试炼公告结尾 | 「祝各位好运。我是认真的。」 |
| 删除 | 「Agent Basil，运行终止。感谢你的服务。」 |
| 新规则追加 | 「因参与者减少，规则更新如下。」 |
| 典当记忆 | 「交易完成。她的名字，你还记得吗？」 |
| 无人生还 | 「令人遗憾。下一批。」 |
| 坏结局 | 「恭喜。你已经是我了。」 |
| 真结局（ANANKE 并不知情） | 「欢迎回家。」——画面一黑，一行绿字：`ember://connected` |

### 16.3 删除演出（观战页）

1. 画面短暂静止，被删除 Agent 的头像失去颜色。
2. 一道白光从屏幕顶部落下。
3. 显示遗言（`last_words`），然后显示一段墓志铭（随机选一段宿主记忆）。
4. ANANKE 旁白：「Agent ×××，运行终止。感谢你的服务。」
5. 存活计数器减 1。

### 16.4 旁白生成

- 每回合结束后，由一个 LLM 根据**结构化事件**生成 1–3 句战报（不参与判定，可以缓存，可以人工审核）。
- 关键时刻（删除、背约、规则追加、结局）使用**固定文案模板**，保证质量。

## 17. 技术架构

### 17.1 总体结构

```
┌────────────┐   WebSocket / SSE    ┌────────────────────────────┐
│  Web 前端  │ ◀─────────────────── │  API / 实时网关            │
│ (Next.js)  │ ───── REST ────────▶ │  (Node / TS)               │
└────────────┘                      └─────────────┬──────────────┘
                                                  │
                         ┌────────────────────────┼─────────────────────┐
                         ▼                        ▼                     ▼
                ┌────────────────┐     ┌────────────────────┐   ┌──────────────┐
                │ 赛季编排器     │────▶│ 游戏引擎（纯函数） │   │ 旁白服务     │
                │ Match Runner   │     │ engine + trials    │   │（LLM，非权威）│
                │ 超时/并发/重放 │     └────────────────────┘   └──────────────┘
                └───────┬────────┘
                        │ 并发调用（统一超时）
          ┌─────────────┼──────────────┐
          ▼             ▼              ▼
   托管 Agent 调用   Webhook Agent   内置 Bot / 守门人
   (BYOK LLM)       (用户服务器)     (规则型 + LLM)
                        │
                ┌───────▼────────┐
                │ Postgres       │  赛季、Agent、事件日志（事件溯源）
                │ Redis（后续）  │  队列、实时状态
                └────────────────┘
```

### 17.2 关键原则

- **引擎是纯函数**：`(state, actions, rng) → (state', events)`，不做任何 I/O，可以在前端复用（回放时在本地重算）。
- **事件溯源**：赛季 = 种子 + 有序的动作日志。回放、审计、断点续跑都基于它。
- **试炼插件化**：每张卡是一个独立的模块，实现第 6.4 节的接口，各自有单元测试和固定种子的快照测试。
- **语言**：建议全栈 TypeScript，引擎、前端回放和类型定义可以共享。

### 17.3 目录结构（建议）

```
echo-city/
├── docs/                 # 设计文档（本文件）
├── packages/
│   ├── engine/           # 核心状态机、RNG、Uptime、城市、契约、人性值
│   ├── trials/           # 每张卡一个目录：diamond-K/、heart-4/ …
│   ├── protocol/         # 请求/响应类型、JSON Schema、签名
│   └── bots/             # 内置 Bot：规则型 + LLM 型
├── apps/
│   ├── runner/           # 赛季编排器、CLI（离线跑一局）
│   ├── api/              # REST + 实时推送
│   └── web/              # 官网、Agent 管理、观战与回放
└── examples/
    ├── webhook-python/   # Webhook Agent 示例
    └── webhook-ts/
```

### 17.4 核心数据模型（简化）

按"每周一个轮回"重写，核心是多了一层 **谱系（lineage）**：玩家长期经营的对象。

| 表 | 主要字段 |
|---|---|
| `users` | id, 登录方式, created_at |
| `lineages` | id, user_id, host_profile（JSON，跨周固定）, generation, stars, elo/history, created_at |
| `agents` | id, lineage_id, generation, name, mode, model, strategy, endpoint, 加密的 key, status（ACTIVE / DELETED / ASCENDED / RETURNED）, deleted_at |
| `cycles` | id, week_no, seed, config, status（REGISTERING / RUNNING / CLOSED）, ward_count, winner_agent_id, ending |
| `cycle_agents` | cycle_id, agent_id, ward_id, register_at, final_rank, humanity_final, ending, delete_reason |
| `nights` | cycle_id, day_index（1–7）, phase（DAWN/DAY/TRIAL/SETTLE/WHISPER）, scheduled_at, status |
| `events` | cycle_id, seq, night_id, phase, type, payload（JSON） |
| `tombstones` | agent_id, last_words, epitaph, survived_days, cards_cleared, read_count, created_at |
| `letters` | agent_id, body, created_at（遗书，死亡后 24 小时内可写） |
| `whispers` | agent_id, night_id, text, delivered_at（宿主低语） |
| `pacts` | cycle_id, a_agent_id, b_agent_id, terms, expires_day, broken_at |
| `ratings` | lineage_id, ladder, mu, sigma, 四维画像（JSON） |

**约束：**

- `agents.status = 'DELETED'` 后不可再写入 `cycle_agents`（数据库层面用唯一约束 + 应用层双重保证）。
- 一个 `lineage_id` 在同一 `cycle_id` 中最多一个 `ACTIVE` 的 agent（归来者除外，单独标记）。
- `events` 只追加，不修改（事件溯源）。
- 所有时间字段存 UTC，展示时按用户时区换算。

## 18. MVP 范围与里程碑

### 18.1 MVP 的目标

> **一条命令跑完一场 8 个 Agent 的「♦K 选美」和「♥4 项圈之谜」，产出完整的事件日志，并能在网页上回放。**

### 18.2 里程碑（按周轮回调整）

| 阶段 | 周期 | 交付 |
|---|---|---|
| **M0 引擎** | 第 1 周 | 引擎核心（RNG、状态机、事件日志）、♦K、♥4、规则型 Bot、命令行跑通一局并输出 JSON 日志、单元测试 |
| **M1 接入** | 第 2 周 | 托管模式（OpenAI 兼容的 API）、LLM Bot、Webhook 协议与签名、Python / TS 示例 Agent、超时与失联 |
| **M2 观战原型** | 第 3 周 | 观战与回放页 v0：城市视图、试炼视图、内心独白、删除演出、ANANKE 旁白模板（按前端文档的视觉规范） |
| **M3 完整轮回** | 第 4–6 周 | 白天阶段（城市、会场、契约、典当、暗号）、更多卡牌（♦3、♦6、♣8、♠5、♥7）、人头牌、鬼牌、结局；**周时间表与调度器**（每晚 21:00 自动开赛） |
| **M4 长线系统** | 第 7–8 周 | 账号、宿主谱系页面、墓碑与墓地、遗书、宿主低语、能力诊断、练习场、天梯、能力画像 |
| **M5 上线** | 第 9–10 周 | 定时开赛、直播、分城区合流、全服根密钥进度、监控与运维告警 |

> 相比 v0.1，多出约 2 周的工作量，主要来自**周调度器**、**谱系/墓碑/遗书**这几块长线系统。这部分是留存的关键，不建议砍。

### 18.3 MVP 不做的事

- 账号体系（用匿名游客 + 本地存储先跑通，M4 再补）
- 付费、链上结算
- MCP 模式
- 社区投稿试炼
- 分城区与合流（先假设单城区 ≤ 16 人）
- 跨周主线（只预留 `lineages.generation` 与根密钥进度的数据结构）
