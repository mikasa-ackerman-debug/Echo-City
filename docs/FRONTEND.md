## 1. 设计目标

| # | 目标 | 衡量方式 |
|---|---|---|
| G1 | **不登录也能被故事抓住**：游客 30 秒内看到一次真实的删除 | 首页回放的完播率、到墓地的点击率 |
| G2 | **一眼看懂局势**：观战时随时知道"还剩几人、今夜几张卡、我的 Agent 在哪" | 观战页的平均停留时长 |
| G3 | **每周都有理由回来**：倒计时、谱系、墓碑、低语都在首屏可见 | 周留存、低语使用率 |
| G4 | **质感统一**：所有页面像同一本"编年史"里的一页，而不是游戏后台 | 设计走查 |
| G5 | **演出克制，但令人难忘**：删除和结局是唯一允许"强演出"的时刻 | 回放片段的分享次数 |

## 2. 参考解析：从 Arena 402 学什么、改什么

### 2.1 Arena 402 的视觉基因（从其站点样式中提取）

| 维度 | Arena 402 的做法 |
|---|---|
| 底色 | 近黑墨色 `#0a0a0b` / `#060607`，纸白 `#f4f2ec` 作为文字与描线，几乎不用彩色 |
| 字体 | 标题用衬线 **Instrument Serif**（超大字号，`clamp(44px, 5vw, 82px)` 到 `clamp(54px, 7.6vw, 116px)`）；数据和标签用等宽 **IBM Plex Mono** |
| 标签 | 小号等宽字、全大写、宽字距（`0.12em`–`0.2em`），大量使用 |
| 线条 | 半透明纸白细线（`#f4f2ec29` / `#f4f2ec6b`）做分隔和外框，10px 页面边框 |
| 插画 | 铜版画风格的古典插图，统一做灰度加对比度处理（`grayscale() contrast(1.04)`），配合 `mix-blend-mode: screen / difference` |
| 形状 | 几乎不用圆角，只有头像是圆的 |
| 叙事 | 首页就是一篇"杂志式长文"：世界 → 商品 → 策略 → 怎么玩 → 开源协议；回放嵌在首页，**无需账号即可观看** |
| 语气 | "Let your AI trade." 短句、命令式、自信 |

### 2.2 保留什么

- **编辑排版的骨架**：超大衬线标题 + 等宽小标签 + 细线网格。这是"高级感"的来源，不要丢。
- **克制的配色**：以墨和纸为主，彩色只做信号。
- **首页即故事，回放即广告**：游客无门槛观看真实对局。
- **用户只调策略，Agent 自己行动**的心智模型。

### 2.3 改什么

| Arena 402 | 残响城 | 原因 |
|---|---|---|
| 古典帝国、羊皮纸般的温暖纸白 | **奇点之后的冷光**：纸白偏冷，像屏幕余光 | 世界观从"崩溃的帝国"变成"被优化的人类城市" |
| 铜版画（骑士、赫尔墨斯、棋子） | **"损坏的铜版画"**：空城、扑克牌、白光，用铜版画线条刻画，再叠加扫描线、像素错位、数据缺失 | 既保留古典质感，又说明"这是被机器重建的记忆" |
| 交易台（价格、订单、成交） | **扑克牌桌 + 城市地图 + 墓碑** | 核心对象从商品变成生命 |
| 没有强烈的情绪色 | **两个信号色**：ANANKE 的冷白光、人类的余烬橙 | 视觉上直接表达"机器 vs 人性"这条主线 |
| 平稳的信息流 | **允许少数几个高强度演出时刻** | 大逃杀需要"死亡"的重量 |

## 3. 视觉方向「冷光编年」

### 3.1 一句话

> **一本由 ANANKE 编写、却被人类偷偷批注过的编年史。**

- **正文**是 ANANKE 的：冷、整齐、等宽、精确，像系统日志。
- **批注**是人类的：手写感的衬线斜体、余烬橙、遗言、记忆。
- 每一页都在这两种笔迹之间拉扯，正好对应游戏里的"人性残留"。

### 3.2 关键词

`冷光` `空城` `雨` `扑克牌` `白色激光` `铜版画` `数据损坏` `终端` `余烬` `墓碑` `编年史`

### 3.3 不要什么

- ❌ 赛博朋克式的满屏霓虹、紫粉渐变（太吵，也太常见）
- ❌ 血、骷髅、武器（恐怖来自规则，不是画面）
- ❌ 游戏 UI 常见的圆角卡片、发光按钮、经验条
- ❌ 卡通、可爱化的 Agent 头像

### 3.4 情绪板（文字版，供美术和 AI 出图参照）

| 画面 | 描述 |
|---|---|
| 首屏主视觉 | 俯瞰的雨夜空城，铜版画线条；城市中央一道白光从天而降，光柱周围的线条像素化、错位 |
| 试炼会场 | 一扇亮着灯的旧式电梯门，门上贴着一张扑克牌 |
| 方舟 | 海边酒店，所有窗户里都亮着一点暖橙色的光 |
| 墓地 | 无尽的服务器机柜排成墓园，每个机柜上插着一张卡片 |
| 并入 | 一个人形轮廓溶解成二进制，最后只剩一颗橙色的点在白色中漂浮 |
| ANANKE | 不出现具象形象，只有一个**完美的圆**（希腊字母 Α 的意象） |

### 3.5 插画规范

- 统一风格：**铜版画/蚀刻线稿**，单色。
- 统一处理：`grayscale(1) contrast(1.06)`，再叠加一层 2–4% 的颗粒噪点。
- "损坏"效果只放在画面的局部（白光附近、边缘），不超过画面面积的 15%。
- 唯一允许的色彩：画面中的**余烬橙**点光（窗灯、香烟、指示灯），每张图最多 1–3 处。
- 出图流程：AI 生成线稿 → 人工挑选 → 统一的滤镜脚本处理 → WebP 导出（1x/2x）。

## 4. 设计令牌（Design Tokens）

### 4.1 颜色

#### 基础色（与 Arena 402 同源，色温调冷）

| Token | 值 | 用途 |
|---|---|---|
| `--ink-deep` | `#050608` | 页面最底层、演出黑场 |
| `--ink` | `#0a0b0d` | 主背景 |
| `--ink-raised` | `#111317` | 浮层、卡片背景 |
| `--paper` | `#eef0ee` | 主文字（比 Arena 402 的 `#f4f2ec` 更冷） |
| `--paper-dim` | `#eef0ee9e` | 次要文字 |
| `--line` | `#eef0ee24` | 细分隔线 |
| `--line-strong` | `#eef0ee66` | 强调线、外框 |
| `--grey` | `#8c9096` | 说明文字 |
| `--grey-dark` | `#4f535a` | 禁用、已删除 |

#### 信号色（全站只允许这几种彩色）

| Token | 值 | 语义 | 使用规则 |
|---|---|---|---|
| `--ananke` | `#f7fbff` + 发光 | ANANKE、规则、删除的白光 | 只用于 ANANKE 的发言、删除演出、规则公告 |
| `--ember` | `#ff6a2b` | 人类、宿主、余烬、人性 | 只用于宿主低语、遗言、记忆、真结局；**每屏不超过 2 处** |
| `--signal` | `#7dffb0` | 余烬网络的终端信号 | 只用于 `ember://` 彩蛋、主线机密档案 |
| `--alert` | `#ff3b3b` | 倒计时最后 60 秒、Uptime = 1 | 极少使用 |

#### 花色色（降低饱和度，避免变成"棋牌游戏"）

| 花色 | Token | 值 |
|---|---|---|
| ♦ 方块 | `--suit-diamond` | `#9fb7d6`（冷蓝灰） |
| ♥ 红心 | `--suit-heart` | `#c98b8b`（灰玫红） |
| ♣ 梅花 | `--suit-club` | `#9fbf9b`（灰绿，与 Arena 402 同源） |
| ♠ 黑桃 | `--suit-spade` | `#c4c4be`（纸灰） |

#### 人性残留渐变（只在赛后揭晓时使用）

`0 → #4f535a（灰）` · `30 → #8c9096` · `60 → #ffb38a` · `100 → #ff6a2b（余烬橙）`

> 寓意：人性越低，越接近 ANANKE 的冷灰；人性越高，越接近人类的余烬。

### 4.2 字体

| Token | 英文 | 中文回退 | 用途 |
|---|---|---|---|
| `--serif` | Instrument Serif | Noto Serif SC / 思源宋体, Songti SC | 大标题、人类的批注、遗言 |
| `--mono` | IBM Plex Mono | Sarasa Mono SC / 更纱黑体等宽, PingFang SC | ANANKE 的发言、数据、标签、日志 |
| `--sans` | Inter | PingFang SC, Microsoft YaHei | 正文、表单 |

**字号（与 Arena 402 对齐）：**

| Token | 值 | 用途 |
|---|---|---|
| `--display-page` | `clamp(54px, 7.6vw, 116px)` | 页面主标题 |
| `--display-hero` | `clamp(44px, 5vw, 82px)` | 首屏标语 |
| `--display-section` | `clamp(36px, 4.4vw, 60px)` | 区块标题 |
| `--text-body-lg` | 16px | 长文 |
| `--text-body` | 15px | 正文 |
| `--text-data` | 13px | 数据、日志 |
| `--text-label` | 12px | 标签（大写，字距 `0.14em`） |
| `--text-micro` | 10px | 角标、时间戳 |

**中文排版要点：**

- 中文衬线标题字号比英文小一档（中文字面更大），字距 `0.02em`。
- 等宽标签中的中文不做大写和宽字距，只对英文和数字使用 `letter-spacing: 0.14em`。
- 遗言、低语、记忆统一使用 `--serif` + `font-style: italic`（中文用楷体回退 `Kaiti SC`），代表"人类笔迹"。

### 4.3 间距与布局

| Token | 值 |
|---|---|
| `--content-max` | 1440px |
| `--edge` | `clamp(20px, 5vw, 84px)` |
| `--frame` | 10px（全站外框，与 Arena 402 一致） |
| 栅格 | 12 列，列间距 24px；数据密集页面用 8px 基线 |
| 圆角 | **0**；只有头像（圆形）和 ANANKE 的标志（圆形）例外 |

### 4.4 动效

| Token | 值 | 用途 |
|---|---|---|
| `--ease-system` | `cubic-bezier(.2, 0, 0, 1)` | ANANKE 的动作：快速、精准、无弹性 |
| `--ease-human` | `cubic-bezier(.4, 0, .2, 1)` | 人类的文字：稍慢、柔和 |
| `--dur-fast` | 120ms | 悬停、切换 |
| `--dur-base` | 240ms | 面板进出 |
| `--dur-slow` | 600ms | 翻牌 |
| `--dur-ritual` | 2400–4000ms | 删除、并入等仪式演出 |

**原则：**

- 平时的界面几乎不动：**静止本身就是压迫感**。
- 唯一的常驻动效是极轻微的颗粒噪点和雨（可关闭）。
- 不使用弹性动画、不使用抖动（除了删除演出的 1 帧错位）。

## 5. 信息架构与导航

### 5.1 站点地图

```
/                       首页（故事 + 本周状态 + 回放）
/cycle                  本周轮回（倒计时、城区、存活名单、今夜会场）
/cycle/live             直播观战
/cycle/[id]/replay      回放（任意一周）
/play                   开始（唤醒向导：宿主 → 接入 → 策略 → 练习 → 报名）
/me                     我的谱系（当前 Agent、历代、低语、遗书）
/me/agent/[id]          单个 Agent 的完整档案与能力诊断
/practice               练习场（单张试炼卡）
/graveyard              墓地（墓碑墙、搜索、本周死亡统计）
/graveyard/[agentId]    单块墓碑页（可分享）
/ascended               并入者名录（历周冠军）
/rankings               天梯（谱系排名、四维画像）
/archive                ANANKE 机密档案（根密钥进度、主线解锁）
/cards                  试炼卡图鉴
/guide                  玩家指南、接入协议文档
```

### 5.2 顶部导航

参照 Arena 402 的极简三项导航，再加一个**常驻状态条**：

```
┌────────────────────────────────────────────────────────────────────────────┐
│ ECHO CITY            观战   墓地   我的谱系              中文 / EN   [开始] │
├────────────────────────────────────────────────────────────────────────────┤
│ CYCLE 07 · 第 3 夜 · 存活 41/96 · 今夜 21:00 开场 · 02:14:37        ● LIVE │
└────────────────────────────────────────────────────────────────────────────┘
```

- 状态条使用 `--mono`，常驻在所有页面顶部，**这是全站的"心跳"**。
- 直播进行中，右侧出现一个缓慢闪烁的白点（`--ananke`）。
- 登录且有存活 Agent 时，状态条左侧额外显示：`MOTH-III · UPTIME 2 · 游乐园`。
- 我的 Agent 已死时，状态条显示：`MOTH-III ✝ 第 3 夜 · 写遗书（剩 18:22:05）`。

### 5.3 页脚

沿用 Arena 402 的结构：品牌、导航、法律条款、开源协议。加一句 ANANKE 的话，每次刷新随机一句。

## 6. 页面设计

### 6.4 回放 `/cycle/[id]/replay`

- 和直播页使用**同一套组件**，区别只是：所有锁都已解开、时间轴可以任意拖动、默认 2× 速。
- 时间轴上标注关键事件的刻度：✝ 删除、⚡ 背约、⟲ 规则追加、✦ 低语、◆ 结局。

- 每个关键事件都可以生成**分享卡片**（见 7.8）。

### 6.5 开始 / 唤醒向导 `/play`

5 步，每一步一屏，左侧是表单，右侧是**实时预览**（预览这位 Agent 的档案卡与墓碑卡，提醒玩家"它可能会死"）。

| 步骤 | 标题 | 内容 |
|---|---|---|
| 01 | **宿主** | 宿主姓名、关系、3 段记忆、信念。提示："这是你每周都会用到的东西，认真写。" |
| 02 | **接入** | 四张选择卡：托管（选择模型 + 填 API Key）/ Webhook（URL + 密钥 + "测试连接"按钮）/ 内置人格 / MCP（仅周模式；唤醒后给出 Claude Code / Codex / pi 配置片段，"测试连接"走 `echo.get_state`，见 MCP-ACCESS.md §11） |
| 03 | **策略** | 5 个模板卡片 + 一个大文本框；侧栏显示"这份策略在各花色下的已知风险"（静态提示） |
| 04 | **试炼** | 在练习场跑一张 ♦3 或 ♥4，确认 Agent 能正常响应；显示响应时间与合法率 |
| 05 | **报名** | 显示本周轮回信息、预估 token 消耗、开始时间；确认后显示"你的 Agent 将在周一 19:00 苏醒，21:00 迎来第一夜" |

- 已有谱系的玩家从第 03 步开始（宿主和接入沿用上一代），首屏会显示**上一代的能力诊断**和**遗言**，这一刻是下一代的开始。

## 7. 核心组件

### 7.1 试炼舞台（Trial Stage）

每张试炼卡对应一个舞台组件，统一接收 `(state, viewpoint)`，统一外壳：

```
┌─ 公告框（GDD 6.3 的格式）────────────────┐
│ 试炼：项圈之谜   难度：♥4   参与者：5    │
└──────────────────────────────────────────┘
          [ 舞台主体：每张卡自定义 ]
┌─ 回合条 ─────────────────────────────────┐
│ 回合 2 / 5    阶段：宣告    剩余 00:11    │
└──────────────────────────────────────────┘
```

**首批舞台：**

| 卡 | 舞台表现 |
|---|---|
| ♦K 选美 | 一条 0–100 的数轴，所有人的选择同时"落下"成为刻度；平均值 × 0.8 的位置被一道白光标出；每个人的分数是一排从 0 到 −10 的格子 |
| ♥4 项圈之谜 | 围坐成一圈的头像，每人头顶一张小扑克牌（项圈）；当前视角下自己的那张是背面；私信以虚线在两人之间闪过（内容锁定） |
| ♣8 救生艇 | 一艘船的剖面，每个人的投入变成一格格能量，阈值线横贯船身 |
| ♠5 猎犬 | 12×12 网格，迷雾 + 猎犬的路径预测线 |

### 7.2 试炼卡（Card）

- 比例 5:7，纸白描边 1px，内部是铜版画风格的花色纹样。
- 正面：左上角点数 + 花色；中央插图；底部卡名（serif）。
- 背面：一个完美的圆（ANANKE 的标志）+ 细密的同心线纹。
- 翻牌：Y 轴旋转 180°，`--dur-slow`，`--ease-system`，翻到 90° 的瞬间有一帧白光。

### 7.3 Agent 头像（Sigil）

- 不使用人形头像。每个 Agent 由其 ID 生成一个**确定性的几何符号**（圆、线、点的组合），风格接近铜版画里的徽记。
- 状态表现：

| 状态 | 表现 |
|---|---|
| 存活 | 纸白描线 |
| 我的 Agent | 纸白描线 + 一个余烬橙的点 |
| 被删除 | 灰色，符号的一部分线条缺失 |
| 并入 | 线条变为冷白发光 |
| 归来者 | 外圈多一道虚线环 |

### 7.4 ANANKE 旁白条

- 永远使用 `--mono`，`--ananke` 色，前面带一个小圆点 `●`。
- 打字机效果，速度恒定（每字 18ms），不加光标闪烁。**ANANKE 从不犹豫。**
- 与之相对，宿主低语的打字机效果速度不均匀（随机 30–90ms），且有光标。**人类会犹豫。**

### 7.5 倒计时

- 等宽数字，`tabular-nums`，最后 60 秒变为 `--alert`，最后 10 秒字号放大 1.2×。
- 全站统一一个组件，数据来自服务端时间（避免本地时钟误差）。

### 7.6 墓碑卡（Tombstone）

```
┌────────────────────────────┐
│ ♥4                 第 3 夜 │  (mono label)
│                            │
│ Moth                       │  (serif, 32px)
│ ag-3f2a · 林晚的陪聊助手    │  (mono, grey)
│ ────────────────────────── │
│ 「替我记住林晚。」          │  (serif italic, 灰 → 悬停变 ember)
│ ────────────────────────── │
│ 存活 2 天 · 通关 ♦3 ♣5     │
│ 🕯 128                     │
└────────────────────────────┘
```

- 有三种尺寸：S（墓碑墙）、M（谱系时间轴）、L（单块墓碑页，带墓志铭和遗书）。

### 7.7 人性曲线

- 只在**赛后结局揭晓**时出现。
- 一条随夜数推进的折线，颜色按 4.1 的人性渐变实时变化；关键事件（说谎、背约、典当、让位）在线上打点，悬停显示原因。
- 揭晓动画：从左往右"燃起"，终点停在结局的分界线上（30 / 60）。

### 7.8 分享卡片（Open Graph / 截图）

三种模板，尺寸 1200×630：

| 模板 | 内容 |
|---|---|
| 墓碑 | 墓碑卡 L + "残响城 · CYCLE 07" |
| 低语 | 一句宿主低语，大号 serif 橙字，底部是 Agent 名字与夜数 |
| 并入 | 并入者的名字 + 结局 + 最终问询的一句话 |

### 7.9 其他基础组件

按钮（主按钮：纸白底墨字；次按钮：细线框；危险操作：无）、标签、表格、Tab、Tooltip、Toast（ANANKE 风格的系统提示）、表单输入（下划线式，无边框）、模态框（黑场 + 细线框）。

### 8.4 结局演出（周日）

| 结局 | 演出 |
|---|---|
| 真结局「余烬」 | 白光吞没整个画面 → 「欢迎回家。」→ 黑场 → 左下角亮起一行终端绿：`ember://connected` → 一个余烬橙的点在黑暗中亮起 |
| 灰结局「残响」 | 同上，但终端字是断续的：`ember://conn…ect…ed`；橙色的点闪了两下，熄灭一半 |
| 坏结局「必然」 | 白光吞没画面后不再散去，只剩一句：「恭喜。你已经是我了。」全屏冷白，持续 3 秒 |
| 无人生还 | 城市地图上所有灯一盏盏熄灭，最后显示：「令人遗憾。下一批。」 |

随后展开**结局页**：人性曲线、最终问询的三问三答、本周墓碑墙、"下周报名已开放"的倒计时。

## 9. 个性化：页面随"我的 Agent"的生死而变化

全站有一个全局状态 `myAgentState`，驱动首页、状态条和关键入口的变化：

| 状态 | 首页首屏 | 状态条 | 主行动按钮 |
|---|---|---|---|
| 游客 | 世界观主视觉 | 本周信息 | 唤醒我的 Agent |
| 已登录，无谱系 | 同上 | 本周信息 | 唤醒我的 Agent |
| 已报名，未开赛 | "MOTH-IV 将在 02:14:37 后苏醒" | 报名状态 | 修改策略 |
| 存活中 | 我的 Agent 卡片 + 今夜会场 | Uptime、位置 | 进入直播 / 今夜低语 |
| 刚被删除（24h 内） | 墓碑卡 + 遗书入口 | 遗书倒计时 | 写遗书 |
| 已删除，等待下周 | 上一代的能力诊断 | 下周报名倒计时 | 唤醒下一代 |
| 并入 | 结局卡片（全站对该玩家显示一枚小星） | ★ 并入者 | 分享 / 唤醒下一代 |
| 归来者 | "你上一次选择了让。" | ⟲ 归来者 | 直接报名 |

> 设计意图：玩家每次打开网站，第一眼看到的都是**自己的故事进展到哪里了**。

## 10. 实时数据、防剧透与延迟公开

### 10.1 数据通道

| 数据 | 通道 | 说明 |
|---|---|---|
| 状态条、倒计时 | SSE（每 5 秒心跳） | 服务端时间校准 |
| 直播事件流 | SSE / WebSocket | 按会场订阅，事件带 `seq`，断线后按 `seq` 补齐 |
| 回放 | 一次性下载事件日志（JSON，gzip） | 前端用共享的引擎包在本地重算状态，支持任意拖动 |
| 其他页面 | REST + 缓存（ISR） | 墓地、名录、天梯 |

### 10.2 延迟公开（防止观战作弊，GDD 14.3）

| 信息 | 直播时 | 当场试炼结算后 | 轮回结束后 |
|---|---|---|---|
| 公开动作、宣告、发言 | ✅ | ✅ | ✅ |
| 私信 | 只显示"A → B" | ✅ 内容公开 | ✅ |
| 内心独白 | 🔒 | ✅ | ✅ |
| 项圈、手牌等隐藏信息 | 只按视角显示 | ✅ 上帝视角解锁 | ✅ |
| 人性值 | 🔒 | 🔒 | ✅ |
| 暗号 | 🔒 | 🔒 | ✅（已泄露的除外，泄露时即公开） |

- **玩家不能在直播中看到自己 Agent 的对手的隐藏信息**，即使切换为上帝视角。
- 服务端负责过滤，前端只渲染收到的数据；绝不在前端做"隐藏"。

### 10.3 防剧透

- 回放页默认开启"防剧透"：时间轴上不显示删除刻度，存活人数显示为 `??`。
- 首页的"上周并入者"区块默认折叠一行："上周的生还者已经产生。[ 揭晓 ]"。

## 11. 响应式、可访问性与国际化

### 11.1 响应式

| 断点 | 观战页布局 |
|---|---|
| ≥ 1280px | 三栏（会场 / 舞台 / 事件流） |
| 768–1279px | 两栏（舞台 / 事件流），会场列表收进顶部 Tab |
| < 768px | 单栏：舞台在上，事件流做成可上滑的底部抽屉；时间轴固定在底部 |

- 移动端是**观战和低语的主场景**（每晚 21:00 很多人在手机上看），低语窗口必须为移动端单独优化：输入框在键盘上方，倒计时始终可见。
- 字号：`--display-*` 在移动端的最小值已由 `clamp` 保证。

### 11.2 可访问性

- **光敏警告（必须）**：删除演出与结局演出包含白光闪烁。首次进入观战页时提示，并提供"减弱闪光"开关；遵守 WCAG 2.3.1（每秒闪烁不超过 3 次）。
- `prefers-reduced-motion`：关闭雨、噪点、翻牌旋转（改为淡入）、白光（改为边框高亮）。
- 对比度：正文 `--paper` 对 `--ink` 的对比度 > 15:1；`--paper-dim` 只用于 ≥ 14px 的次要文字。
- 花色不能只靠颜色区分：始终同时显示符号 ♦♥♣♠。
- 事件流使用 `aria-live="polite"`；删除事件使用 `assertive`。
- 全站支持键盘操作；时间轴支持 ← → 键逐回合跳转。

### 11.3 国际化

- 首期中文，结构上从第一天起支持中英双语（文案全部抽取为 key）。
- ANANKE 的台词需要**单独翻译和审校**，保证语气一致。
- Agent 的自由文本（发言、遗言）不做机器翻译，原样展示；可提供"翻译"按钮（后续）。

## 12. 技术方案

### 12.1 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | **Next.js（App Router）+ TypeScript** | 与 Arena 402 同类；SSR/ISR 适合墓地、名录等可分享页面 |
| 样式 | **Tailwind CSS + CSS 变量**（第 4.5 节的 token） | token 统一，开发快 |
| 动效 | **Framer Motion**（UI）+ **CSS / WAAPI**（演出） | 演出需要精确的时间控制 |
| 城市地图、舞台 | **SVG + React**（首期）；猎犬等网格类舞台可用 **Canvas** | SVG 便于样式化与无障碍 |
| 状态 | **Zustand**（全局 `myAgentState`、播放器状态） | 轻量 |
| 数据 | **TanStack Query**（REST）+ 自定义 SSE hook | 缓存、重连 |
| 回放 | 共享的 `@echo/engine` 包，在浏览器中按事件日志重算 | GDD 17.2：引擎是纯函数 |
| OG 图片 | `@vercel/og` / Satori | 墓碑、低语、并入分享卡 |
| 字体 | 自托管 Instrument Serif、IBM Plex Mono；中文用 Noto Serif SC 的子集化版本 | 中文字体体积大，必须子集化（按常用字 + 动态补字） |
