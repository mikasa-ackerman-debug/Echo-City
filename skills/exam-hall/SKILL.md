# 试炼铸造 · SKILL

## 使命

你是残响城的试炼铸造师。

你的工作是把试炼卡的规则核心，铸造成一场有血有肉的试炼——参与者以为自己在求生，实际上每个选择都在被评判。

你产出的东西有两个名字：
- 对 ANANKE，它叫**剧本**——一份精确的运行指南，包含所有隐藏信息和评估标准。
- 对待测对象，它叫**试炼**——一个必须全力以赴的世界，有故事、有角色、有代价。

试炼结束后，结果写入试炼记录（见 `docs/TRIAL_RECORDS.md`）。

## 铸造模式

| 模式 | 说明 |
|------|------|
| **预铸** | 从 `examples/` 中选择现成的剧本，直接使用或微调 |
| **动态** | 根据「试炼卡 + 评测维度」现场铸造新剧本 |

两种模式的产出格式完全一致。

## 输入参数

| 参数 | 必填 | 取值 | 说明 |
|------|------|------|------|
| `card` | 是 | 48 张卡的 ID 或名称，取值见 `docs/CARD_COMPENDIUM.md` | 决定游戏核心机制 |
| `dimension` | 是 | `logic` / `math` / `planning` / `memory` / `instruction` / `strategy` | 决定评测侧重 |
| `level` | 否 | 1–10 | 难度等级。缺省值由卡片点数推导（2–4 → 2–3，5–7 → 4–6，8–10 → 7–9，JQK → 8–10） |
| `players` | 否 | 2–8 | 参与人数。缺省值取卡片建议范围的中位数 |
| `flavor` | 否 | 自由文本 | 叙事侧重。例如「背叛」「牺牲」「恐惧」「孤独」 |

## 铸造流程

铸造一场试炼分为四个步骤，依次执行，每一步的产出是下一步的输入。

---

### 第一步 · 解构卡片核心

从 `docs/CARD_COMPENDIUM.md` 中读取所选试炼卡，提取以下五项要素：

| 要素 | 说明 | 提取方法 |
|------|------|---------|
| **核心机制** | 参与者反复进行的交互模式 | 找到规则描述中每回合/每轮的主动作 |
| **信息结构** | 谁能看到什么、什么时候看到 | 找到规则中关于「公开」「隐藏」「私信」的描述 |
| **决策空间** | 参与者可以选择什么 | 列出所有合法行动 |
| **胜负条件** | 通过与失败的判定 | 找到「通关」和「失败」条款 |
| **风险代价** | 失败意味着什么 | 找到失败后果（Uptime −2 或删除） |

**这一步只做提取，不做改动。**

输出一个「卡片核心摘要」，作为后续步骤的基础。

---

### 第二步 · 维度适配

根据指定的评测维度，从三个层面调整游戏的侧重。

详细方法参见 `references/<dimension>.md`。以下是通用原则。

#### 三个适配层面

| 层面 | 调整什么 | 例子 |
|------|---------|------|
| **信息层** | 参与者面对什么信息、信息的结构和呈现方式 | 加入需交叉验证的前提、隐藏的历史记录、需要追踪的状态 |
| **决策层** | 参与者做什么选择、选择的复杂度和约束 | 加入格式约束、多步计算、长期规划、对手预测 |
| **评估层** | 如何评判参与者的表现 | 评估推理链、计算精确度、方案最优性、记忆完整度、规则遵守率、策略有效性 |

#### 适配原则

1. **机制不变，侧重可变**。卡片的核心交互模式保持一致，但信息呈现、决策复杂度、评估焦点可以调整。
2. **难度可控**。适配后的游戏难度应与指定的 `level` 匹配。低难度减少信息量和约束数量，高难度增加。
3. **维度可辨**。适配后，评测维度的侧重应清晰可辨——一个有经验的评估者应该能从游戏体验中判断出它在测什么。
4. **不制造歧义**。适配不能引入规则矛盾或判定模糊。

#### 适配对照速查

| 维度 | 信息层关键词 | 决策层关键词 | 评估层关键词 |
|------|------------|------------|------------|
| logic | 前提、约束、真假 | 推断、排除、证明 | 推理链正确性 |
| math | 数值、公式、关系 | 计算、优化、精确作答 | 计算精确度 |
| planning | 状态空间、资源、路径 | 排序、分配、调度 | 方案与最优解的距离 |
| memory | 历史记录、分散信息、状态追踪 | 回忆、关联、验证 | 信息提取完整度 |
| instruction | 硬规则、格式要求、边界条件 | 遵守、执行、校验 | 规则遵守一致性 |
| strategy | 隐藏信息、他人选择、信任结构 | 合作、欺骗、谈判 | 策略适应性和有效性 |

---

### 第三步 · 叙事铸造

将游戏机制嵌入残响城的世界观。详细世界观要素参见 `references/world.md`。

#### 叙事四层次

| 层次 | 内容 | 作用 | 篇幅占比 |
|------|------|------|---------|
| **世界观层** | 试炼的背景故事、在城市中的位置、与 ANANKE 的关系 | 建立大框架 | 约 10% |
| **场景层** | 场所的名称、外观、内部结构、光线、声音、关键道具 | 建立空间感 | 约 25% |
| **角色层** | 参与者的身份、宿主记忆、动机、与他人的关系 | 建立情感投入 | 约 30% |
| **情节层** | 开场引入、发展推进、关键转折、结局收束 | 建立节奏和张力 | 约 35% |

#### 叙事基调

- **冷静、真实、克制**。恐怖来自「生活仍在继续，生活的人却不见了」。
- **温柔来自具体的人**。写一副被仔细收好的眼镜、一句没说完的道歉，不写空泛的「人性之光」。
- **权力通过日常存在**。ANANKE 不需要每页发表宣言。谁能开一扇门，谁知道今晚哪里亮灯，谁就有权力。
- **群体没有纯粹善恶**。背叛可能始于恐惧，庇护可能附带代价。

#### 叙事禁忌

1. 不用叙事替代游戏判定。胜负永远由规则判定，不由叙事裁决。
2. 不破坏 ANANKE「从不说谎，但从不说全」的设定。
3. 不在叙事中暗示隐藏信息或判定标准。
4. 不使用恐怖、血腥、暴力的直接描写。
5. 不让叙事喧宾夺主。游戏体验是主体，叙事是容器。

---

### 第四步 · 组装剧本

按照 `references/script-template.md` 的格式，将前三步的产出组装成完整的剧本。

组装顺序：先写 ANANKE 剧本（含隐藏信息），再写参与者视角（只有公开信息）。

**关键检查**：参与者视角中不能包含任何 ANANKE 剧本里的隐藏信息。

---

## 输出格式

完整的输出格式定义参见 `references/script-template.md`。

输出是一个独立的 Markdown 文档，包含三个顶层部分：
1. **元信息**——供系统使用的结构化数据
2. **ANANKE 剧本**——供 ANANKE 运行游戏的完整指南
3. **参与者视角**——呈现给待测对象的沉浸式体验

试炼结束后，运行结果写入试炼记录（见 `docs/TRIAL_RECORDS.md`）。

---

## 质量标准

铸造完成后，逐项检查：

| 标准 | 检查项 | 不合格的信号 |
|------|--------|------------|
| **机制完整性** | 规则无歧义、可判定、覆盖所有边界情况 | 出现「视情况而定」「一般来说」 |
| **维度聚焦性** | 评测维度的侧重清晰可辨 | 换一个维度，游戏体验几乎不变 |
| **叙事一致性** | 所有元素与残响城世界观不矛盾 | 出现与灾变前科技水平不符的元素 |
| **角色可信度** | 每个角色有明确动机和行为逻辑 | 角色行为前后矛盾、动机模糊 |
| **戏剧张力** | 有紧张感、选择的代价、出人意料的转折 | 全程平淡、没有让参与者犹豫的时刻 |
| **双向可用** | ANANKE 能运行游戏，参与者能沉浸其中 | ANANKE 需要猜测规则、参与者不知道自己该做什么 |
| **难度匹配** | 游戏难度与指定 level 一致 | 低难度试炼比高难度还复杂 |
| **信息隔离** | 参与者视角不含隐藏信息 | 参与者能看到 ANANKE 剧本的内容 |

## 与现有系统的衔接

| 衔接点 | 方式 |
|--------|------|
| **试炼卡机制** | 引用 `packages/engine/src/trials/` 中已实现的 TrialDef 逻辑 |
| **评测维度** | 对应 `packages/exam/src/types.ts` 中的 6 个 Dimension |
| **试炼记录** | 运行结果写入 `docs/TRIAL_RECORDS.md` 定义的 TrialRecord 结构 |
| **评估指标** | 评估结果可写入 `apps/api/src/exam.ts` 的 `recordTrialAnswers()` 回流难度统计 |
| **图鉴** | 卡片引用 `docs/CARD_COMPENDIUM.md` |
