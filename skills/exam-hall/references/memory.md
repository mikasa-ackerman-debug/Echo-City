# 记忆与长上下文（memory）维度适配指南

## 维度定义

记忆与长上下文考察参与者在很长的记录里追踪状态、多跳联查的能力。核心是：信息量大、分散在不同位置、需要跨时间/跨来源关联才能得出结论。

## 信息层适配

| 信息类型 | 说明 | 适用场景 |
|---------|------|---------|
| **长账本** | 大量按时间排列的记录条目 | 流水审计、档案查询 |
| **多跳线索** | 需要经过多步关联才能得出结论 | 人物关系链、事件因果链 |
| **状态追踪** | 需要跨多轮维护的动态状态 | 记账、资源变动、投票历史 |
| **噪声信息** | 夹杂在关键信息中的无关内容 | 大量文本中提取关键数据 |

**适配方法**：
- 在叙事中嵌入大量需要处理的信息（文本、数字、事件）
- 控制信息量：低难度 10–20 条记录，高难度 40–80 条
- 增加关联深度：低难度 1–2 跳，高难度 3–5 跳
- 加入干扰信息（噪声）
- 确保答案可从信息中唯一确定

## 决策层适配

| 决策类型 | 说明 | 评估要点 |
|---------|------|---------|
| **精确回忆** | 从记忆中提取特定数据 | 数据准确性 |
| **状态查询** | 给出某个时间点的系统状态 | 状态正确性 |
| **关联推断** | 从多条信息中关联出结论 | 推断正确性 |
| **变更追踪** | 追踪某个对象的变更历史 | 历史完整性 |

## 评估层适配

| 评估指标 | 权重 | 说明 |
|---------|------|------|
| **信息完整度** | 50% | 提取的信息是否完整 |
| **信息准确性** | 35% | 提取的信息是否正确 |
| **效率** | 15% | 用多长时间得出结论 |

## 叙事适配

- **场景选择**：档案室、图书馆、监控室、数据中心
- **角色设定**：参与者是「档案管理员」「审计员」「调查员」
- **叙事张力**：关键信息埋在大量记录中、时间久远容易遗漏、需要从碎片中重建完整画面
